# Mini Work Planner

Migration checkpoint: `planner.snapshot.json` was migrated on a preserved copy
from schema 9 to 21; `planner.snapshot.json.migration.json` records unchanged
fingerprints (display path normalized relative to the repository). The same
snapshot was then converted with `migrate --to` into the record form,
`planner.snapshot.nyrec`; `planner.snapshot.nyrec.migration.json` records the
unchanged snapshot and semantic fingerprints of that conversion. Every existing
stable ID is retained. `runner/Generated.cs` was regenerated through `emitCSharp`
and the documented 13-case check passed. The pre-cutover snapshot is preserved
at tag `archive/legacy-examples-pre-cutover-20261019`.

A tool, created and maintained with a Nyrwvy maintained AuthoringSession, that decides the next action for a single work item.

The semantic source is `planner.snapshot.nyrec`. The CLI does not interpret the snapshot directly; it is only an adapter that calls C# generated from the public `declarations` and `emitCSharp.symbols`.

## Decision model

Inputs:

- `PrerequisiteState = Ready | Waiting | Failed`
- `ExecutionState = NotStarted | Running | Failed | TimedOut | Succeeded`
- `ValidationState = NotRequired | Pending | Passed | Failed`
- `attempts: Int64`
- `maxAttempts: Int64`

Outputs:

- `start`
- `wait`
- `retry`
- `validate`
- `complete`
- `needs-human`

In the maintained policy, if execution has succeeded but validation is Failed, the result is `retry` while retry budget remains and `needs-human` otherwise. In addition, `TimedOut` uses the same retry policy as `Failed`: `retry` if budget remains, `needs-human` otherwise.

## Running

From the repository root:

```sh
dotnet run --project examples/mini-work-planner/runner -- Ready Failed Pending 1 3
```

Output:

```text
retry
```

Examples:

```sh
dotnet run --project examples/mini-work-planner/runner -- Waiting NotStarted NotRequired 0 0
# wait

dotnet run --project examples/mini-work-planner/runner -- Ready Succeeded Failed 0 1
# retry

dotnet run --project examples/mini-work-planner/runner -- Ready Succeeded Failed 1 1
# needs-human

dotnet run --project examples/mini-work-planner/runner -- Ready TimedOut Pending 0 1
# retry

dotnet run --project examples/mini-work-planner/runner -- Ready TimedOut Pending 1 1
# needs-human
```

Input names are case-insensitive.

## Small policy check

```sh
dotnet run --project examples/mini-work-planner/runner -- --test
```

This checks only a small matrix that covers each state branch and the retry boundary.

## Materializing from a successful snapshot

From a current record-form snapshot (`.nyrec`) generated by a maintained AuthoringSession; convert a `workspace.json` first with `migrate --to` from the F# host at tag `fsharp-host-final`:

```sh
python3 examples/mini-work-planner/materialize.py /path/to/workspace.nyrec
```

The script uses only public AuthoringSession operations (`declarations`, `executionReadiness`, `emitCSharp`); it does not author the program and does not read the snapshot's JSON as the semantic authority. It:

1. copies the snapshot to `planner.snapshot.nyrec`
2. opens it with the Zig session host (`npm run build:host`)
3. obtains the public `declarations` / `executionReadiness` / `emitCSharp`
4. generates the runner from the symbol manifest
5. runs the small policy matrix

The outputs are `declarations.json` and everything under `runner/`.
