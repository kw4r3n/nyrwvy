## Demonstrated gap and selected contract

Six fresh baseline application processes/two disposable domains/two SIGKILLs
established that retention of active witnessed object-only/ref-only tails leaves
startup closed before input. Missing original outcomes stay missing. An exact
join or late physical effect supplies no continuation/release authority.

The [separate continuation procedure](https://github.com/kw4r3n/nyrwvy/blob/bca45b30053b68abbfd071480e7c062735f410e6/examples/offline-session-physical-git/CONTINUATION.md)
completes only an inspected owned object/ref tail. It has its own immutable pending
intent, explicit authority, request bytes, original-file inventory and actual
result. Each new command has a separate launch slot and join witness. A distinct
release decision binds the new result and exact observed state. It releases
observation admission with the original pending registry intact. Original and
distinct integrations, new Member admission and discard stay unresolved. Missing
original success/cancellation is never inferred from physical completion.

The example's administrative policy and mechanical custody binding changed.
The registry graph, core/runtime/backend/schema, generic storage and provider
implementation did not change. Public language-composed recovery, renewed mutation
admission and disposition of an interrupted new continuation remain missing.

## Limits

One trusted serialized writer, immutable fixture provisioning and intact flushed
storage are assumed. This is observation release only, retaining one continuation
and release decision per domain. It does not establish arbitrary chained recovery,
future Git mutation, public graph-composed recovery, arbitrary races/escaped
descendants, uncooperative termination, saturated creation/specification feeding,
cancellation beyond shields, Git power-loss durability, storage faults/deletion,
multiple writers, full Unix/index metadata, linked worktrees/live providers,
coherently rewritten historical storage, scale/compaction or peer acknowledgement.
Independent review is required before successor publication. No push, PR, merge,
live provider, user-project recovery, service activation or access change occurred.
