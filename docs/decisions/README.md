# Decisions

**Status:** Current

This area records durable rationale for Nyrwvy's current direction. Decision records explain **why** a constraint exists; current behavior and normative contracts belong in reference/specification documents.

## Registers

- [Foundational decisions](foundational.md) — D-001 through D-015, covering graph authority, semantic operations, stable identity, human presentation, backend-neutral lowering, obligations, atomic publication, documentation language, and the F# semantic core.
- [Milestone 1 decisions](milestone-1.md) — accepted implementation-backed refinements covering snapshot authority, ID lifecycle, full validation, operation ordering, approval binding, system-side ID allocation, review facts, physical boundaries, obligation-state growth, persistence replaceability, and language-growth rules.
- [Milestone 2 decisions](milestone-2.md) — accepted rationale for the first bounded structural editing slice: complete Float64 function-body replacement through a separate structural workflow, fresh system-owned local identities, conservative obligation blocking, structural before/after review, and history-preserving publication.
- [Milestone 2 ListMap decision](milestone-2-listmap.md) — accepted M2-D08 extension adding one shallow specialized ListMap complete-body replacement after the Float64 evaluation.
- [RAST provenance](rast-provenance.md) — later accepted refinement of the earlier RAST relationship: no dedicated provenance framework for conceptual ancestry; ordinary attribution applies to concrete copied or substantially adapted material.
- [Effectful expression ordering](effectful-expression-ordering.md) — accepted rationale for scoped Bind expressions, with existing dependency/match ordering and ambiguous-effect rejection preserved.
- [Targeted expression replacement](targeted-expression-replacement.md) — accepted design for all-uses `GraphNodeId` targeting, retained target identity, nested lexical context, and replacement-local pruning.
- [Staged declaration authoring](declaration-authoring.md) — accepted roadmap beginning with atomic function creation and explicit existing-effect requirement edits before type/effect/capability declaration stages.
- [Concurrency control beyond `ParallelAll`](concurrency-control.md) — accepted direction for a structured task scope with individually started, waited and cancelled tasks, a `TaskWait` time limit with a virtual clock in `runPure`, and the shared-capability guarantee; phases 1 (scope, start, wait, cancel) and 2 (time limits with a virtual clock) implemented.
- [Bool operators, and deferring Map](bool-operators-and-map.md) — accepted dedicated short-circuit `BoolAnd`/`BoolOr` and `BoolNot` with checkable conditional expansions; Map, Set and Bool equality deferred with revisit conditions.
- [Task fields, list indexing, and Map revisited](task-fields-list-indexing-and-map.md) — accepted `Task<T>` fields in declared types (not `TaskScope`) with a transitive capability and `runPure` boundary rule, and `ListItemAt(list, index): Option<T>`; Map revisited and still deferred with a new revisit condition.
- [Value equality, and Map revisited again](value-equality-and-map.md) — accepted structural `ValueEqual(left, right): Bool` over equatable types (not Float64, functions, tasks, capabilities or type parameters, transitively), which also settles Bool equality; Map still deferred with a new revisit condition.
- [List sorting and String ordering](list-sort-and-string-ordering.md) — accepted `StringLessThan(left, right): Bool` in ordinal Unicode code-point order (as Python compares `str`, unlike UTF-16 code-unit order) and `ListSortBy(list, lessThan, context)`, a stable top-down merge sort under a pure `(T, T) -> Bool` callback whose result is fixed by the algorithm even for an inconsistent callback; no key-based sort and no three-way `StringCompare`.
- [String search, affixes and split](string-search-and-affixes.md) — accepted `StringIndexOf`, `StringLastIndexOf` (code-point positions as `Option<Int64>`), `StringStartsWith`, `StringEndsWith` and `StringSplit`: ordinal, never failing, Python `find`/`rfind`/`startswith`/`endswith`/`split(sep)` parity except that `from` clamps like `StringSlice` and an empty separator gives `[text]`; matches never split a surrogate pair.
- [String lowercase and UTF-8 length](string-lowercase-and-utf8-length.md) — accepted `StringToLower(text)`, the culture-invariant Unicode simple (one-to-one) lowercase mapping per code point (unpaired surrogates kept; Python `lower()` parity except `İ` and final sigma, which Python maps with the full, contextual mapping; results follow the runtime's Unicode data), and `StringUtf8ByteCount(text): Int64`, `len(text.encode("utf-8"))` with an unpaired surrogate counting 3 bytes; casefold stays out of scope.
- [String join and list slice](string-join-and-list-slice.md) — accepted `StringJoin(list: List<String>, separator): String`, Python `separator.join(list)`, and generic `ListSlice(list: List<T>, start, end): List<T>`, both bounds clamped to `[0, length]` exactly like `StringSlice` (negative bounds are 0, not counted from the end; `end <= start` gives the empty list); both never fail.
- [String code points and the recursion depth bound](string-code-points.md) — accepted `StringCodePoints(text): List<String>`, each code point as a one-code-point String in linear time (a lone surrogate is its own item, as `StringLength` counts it), so `ListFold` replaces per-character self-recursion; the stack-bound recursion depth (several thousand nested calls) is documented and `runPure` reports an overflow as recursion that was too deep.
- [Float64 conversion and run values](float64-conversion-and-run-values.md) — accepted `Int64ToFloat64(value): Float64` (round to nearest, ties to even, never fails) and Float64 `runPure` values as shortest round-trip JSON numbers with `"NaN"`, `"Infinity"`, `"-Infinity"` and `"-0"` strings, matched bitwise with every NaN equal and no tolerance; no Float64 to Int64 conversion or decimal rounding yet.
- [Compact simulate replies](compact-simulate-replies.md) — accepted compact `simulate*` reviews by default (functions as signature, `resultNodeId` and `nodeCount`; receipts, fingerprints, readiness, diffs, effect evidence, aborts, callers, callees and open obligations kept) with `detail: "full"` for the previous per-node review.
- [Expression recipe bounds](expression-recipe-bounds.md) — accepted 256-node limit for ordinary expression authoring (the M2 bounded Float64 workflow keeps 64) and node-limit diagnostics that report the count and the largest extractable subtrees.
- [Open questions](open-questions.md) — bounded uncertainties that remain open, partial, or intentionally deferred.

Where a later accepted decision explicitly refines an earlier one, use the later decision for the refined scope rather than treating both texts as competing current rules.
