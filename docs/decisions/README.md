# Decisions

**Status:** Current

This area records durable rationale for Nyrwvy's current direction. Decision records explain **why** a constraint exists; current behavior and normative contracts belong in reference/specification documents.

## Registers

- [Foundational decisions](foundational.md) — D-001 through D-015, covering graph authority, semantic operations, stable identity, human presentation, backend-neutral lowering, obligations, atomic publication, documentation language, and the F# semantic core.
- [Milestone 1 decisions](milestone-1.md) — accepted implementation-backed refinements covering snapshot authority, ID lifecycle, full validation, operation ordering, approval binding, system-side ID allocation, review facts, physical boundaries, obligation-state growth, persistence replaceability, and language-growth rules.
- [Milestone 2 decisions](milestone-2.md) — accepted rationale for the first bounded structural editing slice: complete Float64 function-body replacement through a separate structural workflow, fresh system-owned local identities, conservative obligation blocking, structural before/after review, and history-preserving publication.
- [Milestone 2 ListMap decision](milestone-2-listmap.md) — accepted M2-D08 extension adding one shallow specialized ListMap complete-body replacement after the Float64 evaluation.
- [RAST provenance](rast-provenance.md) — later accepted refinement of the earlier RAST relationship: no dedicated provenance framework for conceptual ancestry; ordinary attribution applies to concrete copied or substantially adapted material.
- [Effectful expression ordering](effectful-expression-ordering.md) — accepted rationale for scoped Bind expressions, with existing dependency/match ordering and ambiguous-effect rejection preserved.
- [Effect ordering checked at proposal time](proposal-time-effect-ordering.md) — accepted one shared `GraphOrder` ordering rule for semantic admission and lowering, applied at proposal and commit to every added, edited or newly ambiguous function with or without Abort; full validation keeps the historical abort-only rule so earlier snapshots still open.
- [Targeted expression replacement](targeted-expression-replacement.md) — accepted design for all-uses `GraphNodeId` targeting, retained target identity, nested lexical context, and replacement-local pruning.
- [Staged declaration authoring](declaration-authoring.md) — accepted roadmap beginning with atomic function creation and explicit existing-effect requirement edits before type/effect/capability declaration stages.
- [Concurrency control beyond `ParallelAll`](concurrency-control.md) — accepted direction for a structured task scope with individually started, waited and cancelled tasks, a `TaskWait` time limit with a virtual clock in `runPure`, and the shared-capability guarantee; phases 1 (scope, start, wait, cancel) and 2 (time limits with a virtual clock) implemented.
- [Bool operators, and deferring Map](bool-operators-and-map.md) — accepted dedicated short-circuit `BoolAnd`/`BoolOr` and `BoolNot` with checkable conditional expansions; Map, Set and Bool equality deferred with revisit conditions.
- [Task fields, list indexing, and Map revisited](task-fields-list-indexing-and-map.md) — accepted `Task<T>` fields in declared types (not `TaskScope`) with a transitive capability and `runPure` boundary rule, and `ListItemAt(list, index): Option<T>`; Map revisited and still deferred with a new revisit condition.
- [Value equality, and Map revisited again](value-equality-and-map.md) — accepted structural `ValueEqual(left, right): Bool` over equatable types (not Float64, functions, tasks, capabilities or type parameters, transitively), which also settles Bool equality; Map still deferred with a new revisit condition.
- [List sorting and String ordering](list-sort-and-string-ordering.md) — accepted `StringLessThan(left, right): Bool` in ordinal Unicode code-point order (as Python compares `str`, unlike UTF-16 code-unit order) and `ListSortBy(list, lessThan, context)`, a stable top-down merge sort under a pure `(T, T) -> Bool` callback whose result is fixed by the algorithm even for an inconsistent callback; no key-based sort and no three-way `StringCompare`. Order 48 added `ListMinBy(list, lessThan, context): Option<T>`, the first smallest item.
- [String search, affixes and split](string-search-and-affixes.md) — accepted `StringIndexOf`, `StringLastIndexOf` (code-point positions as `Option<Int64>`), `StringStartsWith`, `StringEndsWith` and `StringSplit`: ordinal, never failing, Python `find`/`rfind`/`startswith`/`endswith`/`split(sep)` parity except that `from` clamps like `StringSlice` and an empty separator gives `[text]`; matches never split a surrogate pair.
- [String lowercase and UTF-8 length](string-lowercase-and-utf8-length.md) — accepted `StringToLower(text)`, the culture-invariant Unicode simple (one-to-one) lowercase mapping per code point (unpaired surrogates kept; Python `lower()` parity except `İ` and final sigma, which Python maps with the full, contextual mapping; results follow the runtime's Unicode data), and `StringUtf8ByteCount(text): Int64`, `len(text.encode("utf-8"))` with an unpaired surrogate counting 3 bytes; casefold stays out of scope.
- [String code point conversion](string-code-point-conversion.md) — accepted `StringFromCodePoint(code): Option<String>` and `StringToCodePoint(text): Option<Int64>`, Python `chr` and `ord` with `None` where Python raises; surrogate codes 0xD800..0xDFFF are accepted as unpaired surrogate code units, so JSON `\ud83d\ude00` escapes decode one at a time and concatenate to the pair; no code-point-at-index operation.
- [Float64 decimal text](float64-decimal-text.md) — accepted `Float64ToString(value): String`, Python `repr` (shortest round-trip digits, exponent form when the decimal point position is <= -4 or > 16, `nan`/`inf`/`-0.0`), and `StringParseFloat64(text): Option<Float64>`, Python `float` on the JSON number grammar with leading zeros, correctly rounded, a signed infinity on overflow; no precision formatting.
- [String spans](string-spans.md) — accepted `StringSpan(value, set, from): Int64` and `StringSpanBack(value, set, end): Int64`, the code-point positions where a run of `set` members ends scanning forward or backward (Python `lstrip(set)`/`rstrip(set)` as positions; bounds clamped like `StringSlice`; an empty set gives the clamped bound), so `strip(set)` is one `StringSlice` over both; positions rather than a `StringTrim`, since three of probe 5's four uses need positions; both never fail.
- [String split lines](string-split-lines.md) — accepted `StringSplitLines(value, breaks): List<String>`, the lines of `value` split at any code point of the `breaks` String (membership as in `StringSpan`), with `\r\n` as one break when both halves are members and Python `splitlines` edges (`""` gives `[]`, a final break adds no empty line); an explicit set rather than a fixed Python set, since the port needs both `str.splitlines` and `bytes.splitlines`; never fails.
- [String join and list slice](string-join-and-list-slice.md) — accepted `StringJoin(list: List<String>, separator): String`, Python `separator.join(list)`, and generic `ListSlice(list: List<T>, start, end): List<T>`, both bounds clamped to `[0, length]` exactly like `StringSlice` (negative bounds are 0, not counted from the end; `end <= start` gives the empty list); both never fail.
- [Result folds that stop at the first Err](result-fold-short-circuit.md) — accepted `ListEffectFold` with a pure folder returning `Result<S, E>` for seed `S` as the pure fold that stops at the first `Err` (no new construct, no `ListFold` mode); the C# loop now ends at the first `Err`, and `ListFold` rejects a Result folder with a message naming `ListEffectFold`.
- [String code points and the recursion depth bound](string-code-points.md) — accepted `StringCodePoints(text): List<String>`, each code point as a one-code-point String in linear time (a lone surrogate is its own item, as `StringLength` counts it), so `ListFold` replaces per-character self-recursion; the stack-bound recursion depth (several thousand nested calls) is documented and `runPure` reports an overflow as recursion that was too deep.
- [Tail self-calls as loops](tail-self-calls.md) — accepted (order 49) that a self `DirectCall` in tail position (the body result, a `Bind` body, both `Conditional` branches, every match arm and `otherwise`, and the `right` operand of `BoolAnd`/`BoolOr`, recursively) never grows the stack, as a language guarantee; Execution IR `tailCall` terminator, emitted as a parallel assignment of the parameter locals and a jump to the entry block; mutual recursion out of scope (it needs a dispatch method or a trampoline), with the planned steps recorded; refines the recursion depth bound of the string code points decision.
- [ListLast and ListDropLast](list-last-and-drop-last.md) — accepted `ListLast(list): Option<T>` and `ListDropLast(list)` (order 50): stack peek and pop in constant time, the pop sharing the list's store; a push after a pop still copies, and a persistent-vector `NyList<T>` waits for a program that exceeds a run limit because of it
- [ListIndexOf and ListFindIndex](list-index.md) — accepted `ListIndexOf(list, item)` for an equatable item type and `ListFindIndex(source, predicate, context)`, both `Option<Int64>` of the first match (order 51)
- [Persistent-vector List](persistent-vector-list.md) — accepted `NyList<T>` as a 32-way persistent vector with a tail (order 52): push, pop, peek, item-at and a slice from 0 share nodes, so a push after a pop copies at most 32 items; no language or schema change
- [ListLastIndexOf and a smaller-side SetDifference](list-last-index-and-set-difference.md) — accepted `ListLastIndexOf(list, item)`, the last equal item's index found from the end, and a `SetDifference` that walks the smaller right set (order 53)
- [SetIsSubset and MapUnion](set-is-subset-and-map-union.md) — accepted `SetIsSubset(left, right)`, Python `left <= right`, and `MapUnion(left, right)`, Python `left | right` with the right value winning on a shared key, left's keys in place and right's new keys after them (order 60)
- [List slices that share structure](list-slice-sharing.md) — accepted a `ListSlice` from any start that shares the persistent vector's nodes through a start position (order 55), so a breadth-first dequeue copies nothing; a slice keeping fewer than half of the positions up to its end copies instead; no language or schema change
- [Self calls that keep unlisted arguments](self-call-keep-unlisted.md) — accepted `"keepUnlisted": true` on a name-resolved self-call `directCall` (order 54): unnamed parameters pass through unchanged, expanded to the full call when the recipe is read
- [Float64 conversion and run values](float64-conversion-and-run-values.md) — accepted `Int64ToFloat64(value): Float64` (round to nearest, ties to even, never fails) and Float64 `runPure` values as shortest round-trip JSON numbers with `"NaN"`, `"Infinity"`, `"-Infinity"` and `"-0"` strings, matched bitwise with every NaN equal and no tolerance; no Float64 to Int64 conversion or decimal rounding yet.
- [The Bits32 domain](bits32-domain.md) — accepted a separate `Bits32` primitive (exactly 32 bits, equatable, no literal, C# `uint`) with total `Bits32FromInt64` (low 32 bits), `Bits32ToInt64` (unsigned), Xor/And/Or/Not, wrapping Add, `RotateRight` (amount floor-modulo 32) and logical shifts (amount <= 0 unchanged, >= 32 zero), and unsigned decimal run values; no other widths, reinterpretation or generic `Bits<N>`.
- [Product update](product-update.md) — accepted `ProductUpdate(typeId, source, fields)`, a copy of a product with at least one named field replaced and every other field kept (Python `dataclasses.replace`), emitted as a C# `with` expression; kept fields are not defaults, so adding a field needs no plan for it, while removing an updated field is rejected; no nested paths or variant updates.
- [Standard operations with no choice to make](standard-operations.md) — accepted adding commonly needed operations without an observed cost when IEEE 754 or an obvious definition fixes their meaning; added `ListReverse` and the Float64 operations `Sqrt`, `Abs`, `Negate`, `Floor`, `Ceiling` and `Truncate`; operations with a choice to make (`ListRange`, hexadecimal text, `StringToUpper`, Int64 `Abs`) still wait.
- [Standard operations with an owner choice](standard-operation-choices.md) — accepted `ListRange(start, end)` and `StringRepeat(text, count)`, where a result too large to allocate is a host failure rather than `Option` or clamping; `Int64ToHexString` and `StringParseInt64Hex` signed like `Int64ToString` (`-ff` for -255) with a strict parse; and `Int64Min`, `Int64Max` and `Int64WrappingAbs` (`Int64.MinValue` gives itself); `StringToUpper` still waits.
- [Float64 to Int64: ties-to-even rounding and floor](float64-to-int64.md) — accepted `Float64RoundToInt64` and `Float64FloorToInt64`, both `Float64 -> Option<Int64>`: Python `round(x)` (ties to even) and `math.floor(x)`, `None` for NaN, the infinities and results outside Int64; never fail; truncation, ceiling and decimal rounding not added, with revisit conditions. Its tie rule was amended by order 43.
- [String uppercase](string-uppercase.md) — accepted `StringToUpper(text)`, the culture-invariant Unicode simple uppercase mapping per code point with `ß` mapped to CAPITAL SHARP S `ẞ`, so the length never changes and `StringToLower` is its inverse.
- [MatchUnion arms shared by several variants](match-union-shared-arms.md) — accepted arms that name several variants with one body and no field bindings, and a recipe `otherwise` arm expanded to an explicit variant list, so every variant stays named and the persisted form of one-variant arms is unchanged.
- [Set](set.md) — accepted `Set<T>` of equatable items in insertion order, immutable and persistent, with `SetEmpty`, `SetFromList`, `SetInsert`, `SetContains`, `SetRemove`, `SetSize` and `SetToList`, and (order 47) `SetUnion`, `SetIntersection` and `SetDifference`.
- [Map](map.md) — accepted `Map<K, V>` with keys of any equatable type compared with `ValueEqual`, iteration in insertion order, immutable persistent values (O(log n)), `MapEmpty`, `MapInsert`, `MapGet`, `MapContainsKey`, `MapRemove`, `MapSize`, `MapKeys`, `MapValues`, `MapFold` and `MapFromList`, later `MapFilter` (order 47) and `MapGetOrDefault` and `MapMapValues` (order 48); maps not equatable; Set later; no general tuple type.
- [Rounding half away from zero, and decimal places](rounding-half-away-from-zero.md) — accepted `Float64RoundToInt64` rounding half away from zero (amending order 34) and `Float64Round(value, digits): Float64`, decimal places half away from zero on the shortest decimal text (`2.675` to 2 places is 2.68).
- [Checked Int64 arithmetic](checked-int64-arithmetic.md) — accepted `Int64CheckedAdd`, `Int64CheckedSubtract` and `Int64CheckedMultiply`, all `(Int64, Int64) -> Option<Int64>`: the exact result, or `None` outside Int64; an owner choice on probe 20's one observation.
- [UTF-8 decoding with replacement](utf8-decode.md) — accepted `StringDecodeUtf8Lossy(bytes): String`, Python `bytes.decode("utf-8", "replace")` over bytes held one per code point (one U+FFFD per maximal ill-formed subpart; a code point above U+00FF reads as byte 0xFF); never fails; strict and `surrogateescape` modes and a bytes type not added, with revisit conditions.
- [Compact simulate replies](compact-simulate-replies.md) — accepted compact `simulate*` reviews by default (functions as signature, `resultNodeId` and `nodeCount`; receipts, fingerprints, readiness, diffs, effect evidence, aborts, callers, callees and open obligations kept) with `detail: "full"` for the previous per-node review.
- [Recursive type declarations](recursive-type-declarations.md) — accepted creation of a type group in one reviewed transaction (`simulateCreateTypesByName`), where a named field type resolves first to a group member and then to a published type, so self-recursive and mutually dependent types such as `Json` are declared by name (order 26).
- [Expression recipe bounds](expression-recipe-bounds.md) — accepted 256-node limit for ordinary expression authoring (the M2 bounded Float64 workflow keeps 64) and node-limit diagnostics that report the count and the largest extractable subtrees.
- [Capability operation signature migration](capability-operation-signature-migration.md) — accepted migrating one operation's argument and result types (order 58) as one reviewed proposal with a complete set of repairs for its implementations and affected callers; IDs, parameter shape, effects and `FailureType` unchanged
- [String replace and trim](string-replace-and-trim.md) — accepted `StringReplace(value, pattern, replacement)`, Python `str.replace(old, new)` in ordinal code-point matches that never split a surrogate pair, with an empty pattern returning `value` unchanged, and `StringTrim`, `StringTrimStart` and `StringTrimEnd`, which remove Unicode White_Space (`char.IsWhiteSpace`; unlike Python, U+001C–U+001F are kept) (order 59).
- [Int64 bitwise operations and Float64Min and Float64Max](int64-bitwise-and-float64-min-max.md) — accepted `Int64BitAnd`, `Int64BitOr`, `Int64BitXor`, `Int64BitNot`, `Int64ShiftLeft` and `Int64ShiftRight` with the shift count clamped to 0..64, and IEEE 754-2019 `Float64Min` and `Float64Max` (order 61), as ordinary builtins ahead of probe evidence
- [List positional updates](list-positional-update.md) — accepted `ListSetAt(list, index, item)`, `ListInsertAt(list, index, item)` and `ListRemoveAt(list, index)`, each returning a new `List<T>` and never failing (order 62): set and remove return the list unchanged for an index outside `[0, length)` (Python raises `IndexError`), insert clamps the index to `[0, length]` like `list.insert` for non-negative indexes; set is O(log n), insert and remove O(log n + length − index).
- [ListZipWith and ListFlatMap](list-zip-with-and-flat-map.md) — accepted `ListZipWith(left, right, combiner, context)`, a Python-`zip` combination to the shorter length (there is no tuple type), and `ListFlatMap(source, mapper, context)`, the mapper's lists concatenated in linear time (order 63)
- [Option and Result combinators](option-result-combinators.md) — accepted `OptionGetOrDefault(option, default)`, `OptionMap`, `OptionAndThen`, `ResultMap`, `ResultMapErr` and `ResultAndThen` with Rust's semantics (order 64): the default is always evaluated, a pure callback with context runs only for the case it names, and `ResultAndThen`'s binder keeps the source's error type; an owner choice ahead of probe evidence.
- [Option and Result accessors](option-result-accessors.md) — accepted `ResultGetOrDefault(result, default)`, `OptionOkOr(option, error)`, `ResultOkValue`, `ResultErrValue`, `OptionIsSome` and `ResultIsOk` with Rust's semantics (order 65), every operand evaluated; `OptionIsNone` and `ResultIsErr` are not added because they are `BoolNot` of the last two.
- [ListContains](list-contains.md) — accepted `ListContains(list, item): Bool`, Python `item in list` over an equatable item type as `ValueEqual` compares, stopping at the first equal item (order 66); kept beside `ListIndexOf` for the reason `StringContains` was kept beside `StringIndexOf`.
- [Set callbacks](set-callbacks.md) — accepted `SetFold(set, seed, folder, context)`, `SetFilter(set, predicate, context)` and `SetMap(set, mapper, context): Set<U>` with `U` equatable, the List and Map callback operations over a Set in insertion order (order 68); `SetAny` and `SetAll` are not added because Map has no counterpart and `ListAny` over `SetToList` covers them.
- [ListMaxBy](list-max-by.md) — accepted `ListMaxBy(list, lessThan, context): Option<T>`, the counterpart of `ListMinBy` under the same callback, replacing the best only when `lessThan(best, item)` holds so the first of equal largest items wins as Python `max` (order 69).
- [Float64 floor modulo](float64-floor-modulo.md) — accepted `Float64FloorModulo(left, right)`, Python's float `%` (`fmod` moved by one divisor, a nonzero result signed like the divisor as `Int64FloorModulo`), with NaN for a zero divisor, an infinite dividend or a NaN operand as `Float64Divide` follows IEEE where Python raises (order 70).
- [StringLastIndexOfBefore](string-last-index-of-before.md) — accepted `StringLastIndexOfBefore(value, substring, end): Option<Int64>`, Python `rfind(sub, 0, end)` with `end` clamped like a slice bound, as a separate kind beside `StringLastIndexOf` rather than an optional operand (order 71).
- [UTF-8 encoding](string-encode-utf8.md) — accepted `StringEncodeUtf8(text): String`, the inverse of `StringDecodeUtf8Lossy` over the latin-1 byte form (order 67); an unpaired surrogate encodes as U+FFFD, the 3 bytes `StringUtf8ByteCount` counts, so the encoded length always equals the count.
- [Generic Product and Union types](generic-types.md) — accepted type parameters on Products and Unions, type arguments on named types, derived or explicit type arguments on construction, regular recursion and no constraints; snapshot JSON 18.
- [Map and Set equality](map-set-equality.md) — accepted `Set<T>` and `Map<K, V>` with equatable values as equatable, compared by content regardless of insertion order (Python `set`/`dict` `==`).
- [Recipe kinds retired from the agent reference](retired-authoring-kinds.md) — accepted leaving `stringEqual`, `int64Equal` and `mapGetOrDefault` out of the recipe reference in favour of `valueEqual` and `optionGetOrDefault` of `mapGet`, and `int64GreaterThan`, `int64LessThanOrEqual` and `int64GreaterThanOrEqual` in favour of `int64LessThan` with swapped operands or under `boolNot`, while readers, codecs and the backend keep supporting existing graphs.
- [Capability operation `FailureType` retired](capability-failure-type-retired.md) — accepted retiring the meaningless optional `FailureType` of capability operations: authoring rejects a non-null `failureType`, readers keep existing ones until the legacy cutover removes the field, and expected failures are the operation's `Result` result type.
- [Declaration visibility, private by default](declaration-visibility.md) — accepted a visibility (exported or private) on types, effects, capabilities and functions: new declarations are private unless created with `exported: true`, `setExported` changes one, a dependency's private declarations are hidden from `declarations`, name resolution and new references (`ImportedDeclarationNotExported`), an upgrade preview lists exported changes first, and snapshot JSON 21 / Nyason v17 writes `exported` explicitly while older documents read as all-exported with their fingerprints unchanged.
- [Structural renames and removals](structural-renames-and-removals.md) — accepted exact-ID renames of fields, variants, parameters, effects, capabilities and capability operations and their parameters (display name only, unique within the owning scope), and `removeFunctionParameter` and `removeUnionVariant`, which repair direct calls and match arms and reject what would need a choice.
- [Authoring-surface queries and name-resolved parity](authoring-surface-queries-and-parity.md) — accepted `addCapabilityOperation` with one implementation plan per `capabilityConstruct` of the Capability (the exhaustive-plan rule of `addProductField`), the `references` query listing every referencing site of a declaration or member (also the `references` view of `nyrwvy_inspect`) with deletion rejections that list every blocking issue, the `proposals` listing with `pendingProposalCount` in `status`, `verifyChangeByName`, `simulateParameterTypeMigrationByName`, `simulateResultTypeMigrationByName`, `simulateAddUnionVariantLikeByName` and every operation kind in `simulateOperationsByName`, and the rename of the `Fieldless` Union variant evolution workflow; its deferred plain `addUnionVariant` was then accepted and implemented as a `simulateOperations` member that takes one arm recipe per `matchUnion` over the Union (materialized in each arm's scope, with the new variant's fields as pattern slots), chosen over missing-arm obligations and default arms.
- [Open questions](open-questions.md) — bounded uncertainties that remain open, partial, or intentionally deferred.
- [A persistent runner process for `runPure`](runpure-persistent-worker.md) — accepted one long-lived runner worker per session that loads each run's build into a fresh load context and runs it on its main thread, keeping the 5 s limit, stack-overflow and crash reporting, output limit, core-dump opt-out and per-run isolation of the former child process; host-source runs keep a fresh process; validation issues and fingerprints are retained per snapshot object.

Where a later accepted decision explicitly refines an earlier one, use the later decision for the refined scope rather than treating both texts as competing current rules.
