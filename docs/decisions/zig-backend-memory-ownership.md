# Memory ownership in the Zig backend

- **Status:** Accepted (owner decisions A–D, 2026-11-01)
- **Progress:** First milestone, Nyrwvy half landed: library mode (see [Library mode as built](#library-mode-as-built)). Remaining for the milestone, on the Rhifill side: the extra `layoutFrame` saved cases (acceptance 1), the C# P/Invoke wiring behind a switch (2) and the p50/p99 and one-hour RSS bench (3). Second milestone, stage (a) of reference counting landed 2026-11-02: counted values, Perceus retain and release in emitted code and a checked runner allocator ([verification](../verification/zig-reference-counting-a-20261102.md)). Its header holds the allocated length beside the `u32` count (8 bytes, so a prefix of a fresh allocation frees exactly). Stage (b) landed 2026-11-02: `errdefer` releases on every instruction that can fail, and counted task and hand-off cell handles, so the leak check runs on every run except one that exceeds 1,024 capability calls ([verification](../verification/zig-reference-counting-b-20261102.md)). Stage (c) landed 2026-11-02: count-of-one reuse, where `ProductUpdate`, list append, concatenation, set-at and slice, String concatenation and Set and Map insert consume their input and update it in place when its count is one; a unique list grows by doubling ([verification](../verification/zig-reference-counting-c-20261102.md), accepted 2026-11-02: doubling growth with up to about twice the length as spare capacity, and concatenation and slice counted as similar updates; the field-read copy in `{ st with items = append(st.items, x) }` remains). Stage (d) landed 2026-11-02 as a smaller change than the trie in [Collections](#decision): a shared list whose length is the number of items its storage owns appends, concatenates and grows in place into spare room, and a shared prefix slice shares the storage, so keeping old versions while appending, and `{ st with items = append(st.items, x) }`, no longer copy; shared `ListSetAt`, insert, remove and slices from a later start still copy ([verification](../verification/zig-reference-counting-d-20261102.md), accepted 2026-11-02 in place of the 32-way trie, along with the 2^31−1 item limit, twice-room copies and half-length shared prefix slices; a ReleaseFast tail loop got about 16% slower, cause not found). Stage (e) landed 2026-11-02: the Set and Map hash index of decision D, an `index` field beside the dense arrays (open addressing over positions, at most half full, none up to 32 scalar or 8 other items), updated in place when its count is one and rebuilt otherwise, with `nyHash` mirroring `nyEqual`; lookups are O(1) expected, a unique insert amortised O(1), a shared insert and every removal O(n), and the language reference records the difference ([verification](../verification/zig-reference-counting-e-20261102.md); accepted 2026-11-02: the index as a field, removal without tombstones, the per-type threshold, the rebuild on a shared insert, twice-room `SetFromList` and `SetUnion` results, and a 4–5% slower ReleaseFast loop over 4–8-key Int64 maps; each simpler choice stays until practical use shows it hurts).
- **Date:** 2026-11-01
- **Plan:** [backend-neutral semantics and generated library bindings](../plans/multi-backend-and-bindings.md#backend-notes), Backend notes (Zig) and Order step 5

The Zig backend runs nearly every program, but its runtime (`tools/zig/emitter/runtime.zig`) takes three shortcuts that are fine for `runPure` and wrong for a long-running program: every String and boxed value lives in one process arena (line 33), every List update copies (line 516), and Sets and Maps look up linearly and copy on update (line 652). Its scheduler is a port of the C# deterministic virtual clock (line 90). The plan already settles the direction (atomic reference counting, count-of-one reuse, persistent collections). This record turns it into a contract before any runtime or emitter change, and fixes the order those changes can land in.

The likely first real use is small: Rhifill's `Screen.Read` (`app/Screen.cs`, about line 204) calls the pure `layoutFrame(List<List<Int64>>, CellGrid): List<List<Int64>>` once per frame, copies the result into `long[][]` and keeps nothing. That use needs neither reference counting nor a scheduler, so this record separates what it needs from what a general production backend needs.

## Settled by the plan (not re-decided here)

- Values are immutable and acyclic, and function values are capture-free function pointers (`functionValueId`), so reference counting reclaims everything without a collector, and function values carry no count.
- Allocation failure and stack overflow are fatal. Pure code has no error union, so a panic in a pure export ends the host process.
- Strings are UTF-8 (scalar values only); host failures are `NyError!T` with the failure in the thread-local `ny_failure` slot.

## Decision

**1. Ownership of generated values (lands after F# removal; see 5).**

- **Representation.** Every heap value (String bytes, boxed Product and Union payloads, List nodes, Set and Map storage, Bytes) carries an 8-byte header before its payload: the `u32` count and a `u32` allocated item count (accepted 2026-11-02; the second field lets a prefix of a fresh allocation free exactly, and the 8-byte payload alignment needs the space anyway). Since stage (d) the count's top bit marks List or String storage with spare room, whose last 4 bytes record how many items it owns, so a List or String holds at most 2^31−1 items; Int64, Float64, Bool, Unit, inline Option and function values carry none. Plain counts (decision A).
- **Owned parameters, owned returns (Perceus).** A call consumes its arguments and returns an owned result. The emitter inserts a retain before each use of a binding except the last, and a release where a binding dies unused (including the arms of a `match` that do not use it: each arm releases what it drops). Borrowed parameters are an optimisation the emitter may add later for a parameter that a function only reads, never a semantic rule.
- **Containers.** Storing a value in a Product, Union, List, Set or Map transfers the reference; reading a field or item retains it. Releasing a container releases its children (iteratively for List spines, so a long list never overflows the stack).
- **Count-of-one reuse.** A `ProductUpdate`, `ListSetAt`, `ListAppend`, `SetInsert`, `MapInsert` and similar update (including list and String concatenation and slice) whose input count is one mutates in place and returns the same storage; otherwise it copies (path-copying for persistent structures). The result is the same either way, so reuse is never observable and needs no parity case of its own.
- **Tail self-calls** stay loops; each iteration releases the previous iteration's dead bindings before rebinding the parameters.
- **Failure paths.** Every `try` on an effectful call has an `errdefer` releasing the owned bindings live at that point, so an abort (fault or cancellation) leaks nothing on its way to `ExceptionCatch`. `UseResource` (emitter `main.zig` about line 1339) keeps releasing the resource on every path; the count release is added beside it, not instead.
- **Tasks.** Starting a task transfers its captured arguments to the task; `TaskWait` returns an owned result and task and hand-off cell handles are counted, and the task's own reference to its result (or a cell's to its value) is dropped with the last handle or the task's run, whichever ends later, not at scope exit, because a handle that escapes its scope can still read the result (accepted 2026-11-02). A cancelled task releases its live bindings through the same `errdefer` path.
- **Leak test.** The runner allocates through a counting allocator (`std.heap.DebugAllocator` in the conformance build) and exits with a dedicated failure when any allocation is live after `main` returns. The parity client already reports a failing run per saved case, so every saved case becomes a zero-leak check with no new protocol. The runner frees a reported failure's message before the check, so an expected-failure case is not a false leak.

**2. Collections.**

- **List:** the persistent vector the C# backend uses (32-way trie with tail, a start position for shared slices, the retention rule of [list slices that share structure](list-slice-sharing.md)), plus count-of-one in-place reuse once 1 lands. Complexity targets are those already documented in the [language subset](../reference/language-subset.md): `ListSetAt` O(log n), insert and remove O(log n + length − index), length O(1). As built (stage (d), accepted 2026-11-02) the List is not the trie: a flat array whose shared appends claim spare room, so shared `ListSetAt`, insert, remove and dequeues still copy in O(n). If a measured workload suffers from those copies, build the trie.
- **Set and Map:** an insertion-ordered dense entry array plus a hash index (open addressing over entry positions), with structural hashing over every equatable type (consistent with `ValueEqual`). Lookup and contains are expected O(1). Insert and remove copy (O(n)) until count-of-one reuse lands, then are O(1) amortised when the input is unique and still O(n) when it is shared, which is weaker than the documented O(log n) for shared values (decision D). Removal compacts by copying while emitted code iterates `.items` directly; tombstones (skipped on iteration, compacted past half) arrive with reuse, when the emitter changes anyway.

**3. Host and C ABI boundary.**

- **Direction.** The first boundary is the inverse of the mapping tables: C# (or C) calls an exported Nyr function. A new emitter **library mode** emits the program without the runner `main` plus one `export fn ... callconv(.c)` per function the workspace marks for export. It reuses the Conversions and Ownership vocabulary of the mapping tables (plan §8 table, [C# mapping tables](csharp-mapping-tables.md)); the C# side is a generated P/Invoke facade like [the C# facade](csharp-facade.md).
- **Marshalling.** Int64, Float64 and Bool pass by value. Bytes and Lists of scalars pass as pointer and length; a nested List of scalars passes as one flat buffer plus row lengths. Strings cross as UTF-8 pointer and length; the C# facade converts to and from UTF-16 (`Encoding.UTF8`), and `Encoding.UTF8` already replaces unpaired surrogates with U+FFFD on the way out, so the Zig side receives well-formed UTF-8 from the generated facade and does not validate it again.
- **Ownership across the boundary.** Arguments are borrowed for the call: the export copies what it keeps. Results are written into a caller-provided buffer when the caller can size it (`layoutFrame` returns `rows × (cols + 1)` positions); otherwise the export returns an owned handle with a generated `ny_free_<type>` function and the facade releases it in `Dispose` (superseded by [exports that keep state](zig-stateful-exports.md): a capability handle is released by its close operation, and value handles, not built, would use one generic `ny_release`). Callbacks into the host are out of scope until plan §5's callback kinds land.
- **Errors and cancellation.** A pure export cannot fail (allocation failure is fatal). An effectful export returns a status code (`0` ok, `1` fault, `2` cancelled) with the message readable through `ny_last_failure` on the calling thread; cancellation enters as a token handle argument that the host signals.
- **Threading.** The runtime's globals (arena, scheduler gate) are process-wide, so exports are serialised by one runtime mutex. A UI host calls from its UI thread; an export that may wait must not be called from a function declared not to wait (plan §3).
- **`hostSources` stays unsupported on Zig** (`tools/zig/host/run_pure.zig` about line 185): it compiles C#. The Zig equivalent is a mapping table binding capabilities to C functions or Zig declarations ([plan §8](../plans/multi-backend-and-bindings.md#8-mapping-tables-and-the-binding-generator), Order step 5, "program-defined and host capabilities"), not a Zig `hostSources`.

**4. Scheduler.** The virtual clock stays the only mode `runPure` and the parity client use. Production adds a real-time mode selected at build time: delays wait on the monotonic clock, waits block on the event they name after releasing `ny_gate` (an OS call such as `Pty.read` or `Fs` releases it too, and reacquires it before touching values), and cancellation from a PTY read or a UI action signals the task's token through the same `NyCancel` path. The one-thread-at-a-time gate stays in both modes (decision A depends on this). Deadlock detection (every waiter fails when nothing can resume) remains only in virtual mode, where it is exact.

**5. Sequencing.** **Unblocked 2026-11-02:** the emitter check and the F# emitter are removed (switch step 5, first part; [verification](../verification/zig-emitter-check-removal-20261102.md)), so changes to the runner output, reference counting included, may merge. The text below records the constraint as it stood. The emitter check byte-compared the Zig emitter's runner with the deprecated F# emitter in the extended suite. `runtime.zig` is one file embedded by both (`Nyrwvy.Backend.Zig.fsproj` as a resource, the Zig emitter by `@embedFile`), so:

- **Before F# removal** (allowed now), two kinds: changes confined to `runtime.zig` that keep every function the emitted code calls and every field it reads (`.items` of a Set, slices for Lists), which covers the Set and Map hash index behind the existing `items` field and the real-time scheduler mode; and additive emitter modes in `main.zig` that `runPure` does not use, so the check never compares them, which covers library mode.
- **After F# removal** ([Zig session host, the switch](zig-session-host.md#the-switch), steps 4 and 5, which also delete `NYRWVY_ZIG_*_CHECK`): anything that changes the runner output, which is all of 1 (retain and release sites, `errdefer`) and the List representation (the emitter writes `[]const T` and iterates slices directly). Retiring the emitter check alone earlier would also unblock them; that is the owner's call, not this record's.

**First milestone (before F# removal).** Library mode exports `layoutFrame`; the export copies its result into the caller's buffer and then resets the arena (`reset(.retain_capacity)`), which bounds memory per call without reference counting. Acceptance:

1. The saved cases for `layoutFrame` (Rhifill has one today, `app/nyr/cases/layoutFrame-1-2-table.json`; add at least empty, wide-only, combining and 300×100 cases) agree between C# and Zig through the parity client.
2. Rhifill calls the Zig export behind a switch and renders identically on the same cases.
3. Measured on one Linux machine with the existing Rhifill bench (`spikes/bench-nyrwvy`): per-frame `layoutFrame` p50 and p99 for C# and Zig at 80×24 and 300×100, and process RSS over a one-hour scrolling run, flat after warm-up.

Reference counting (1) and the persistent List are the second milestone and start right after the first (owner: land it early, not gated on a long-lived program). To unblock it, switch steps 4 and 5 come next; if they lag behind the first milestone, the emitter check is retired early instead of waiting. The emitter check was retired on 2026-11-02, and the F# host was removed the same day (switch step 5 done; [verification](../verification/zig-fsharp-host-removal-20261102.md)).

## Library mode as built

- **Exports.** `<snapshot>.backends.json` gains `"exports": ["<function display name>", ...]` beside `"targets"` (decision C; the sidecar is tool configuration, outside the fingerprint). Each name resolves to exactly one visible function and is exported as the C symbol `ny_<name>`.
- **Generation.** The authoring operation `emitZigLibrary` (optional `output`, a `.zig` path confined like `emitCSharp`'s, and an optional `header`, a `.h` path confined the same way) returns or writes the program without the runner `main` and fakes, plus the exports; the reply lists `{function, functionId, symbol}` and, when a header was requested, `headerPath`. Build it with `zig build-lib -dynamic -lc -O ReleaseSafe <file>.zig -femit-bin=<lib>` (`-lc` because the runtime uses thread-local storage). The emitter's `library` entry is separate from `runner`, so `runPure` output and the emitter check are unchanged.
- **C ABI** (`tools/zig/emitter/library_support.zig`). Int64, Float64 and Bool by value; String as UTF-8 `ptr, len`; `List<Int64|Float64>` as `ptr, len`; a nested list as a flat `ptr`, `row_lens` and `rows`; a non-generic Product as its fields, flattened recursively in field-ID order (the generated doc comment names the order): a field may itself be a String, Bytes, a List, a nested Product, an Option of those, or a handle capability, flattened as on the result side, and a recursive Product is rejected. `List<String>` crosses as a nested list of bytes (the strings concatenated, one length per row, every row checked as UTF-8 before anything is copied). A scalar result goes to `out`; a String or List to `out, out_cap, out_len`; a nested list to `out, out_cap, out_len, out_row_lens, out_row_cap, out_rows`. A Product result gets one set of these per field, in field-ID order; an `Option` result adds `bool *out_some` before its value's parameters, which are written only when it is some. An `Option` argument is the mirror image, except that its value's parameters are always present and always validated, so a none is passed with zero lengths. They nest, except a recursive Product or an `Option` of an `Option`. Status 3 tries every buffer first, so it reports all the lengths at once. A Union result is rejected. Every export returns `c_int`: `0` ok, `1` fault (message through `ny_last_failure(&len)`, per thread, until its next failure or `Err`), `2` cancelled (reserved), `3` a result buffer too small (the lengths written are what is needed; call again, which runs the export again), `4` `Err` of a `Result<_, String>` result (its text through `ny_last_failure`; an `Ok` value is written as any other result). Bytes crosses like a String without the UTF-8 check, and a handle capability as `ny_handle *` (see host bindings). The reply marks an export that may wait with `"mayWait": true` and its `"waitPath"`, and its doc comment says so; the host must not call one from a thread that must not wait. Other types, generic functions, capability parameters other than table-bound ones and names that are not C identifiers are rejected as unsupported; a function that uses tasks is not rejected but has no scheduler I/O to run on (untested). `ny_arena_capacity()` reports the arena's retained bytes, which hold only runtime records since the counted library; a memory check uses process RSS or a checking allocator. `ny_last_failure` and `ny_arena_capacity` are exported by every library, so two Nyr libraries cannot share one process yet. The C# wiring must read the field-ID order from the generated comment (or the `declarations` reply), since IDs do not follow display-name order. The optional C header is built in the same emitter walk as the Zig signatures, so the two cannot drift: one declaration per export, plus `ny_last_failure`, `ny_open_handles` and `ny_arena_capacity`, and for a Product result a `<symbol>_result` struct that names the flattened out parameters after their fields (with the `f_<field-ID>` spellings, because the lowered IR carries no display names) and a `static inline` `<symbol>_into` wrapper that fills it, so a C caller can read a result's fields by name instead of by position; recreating a type mints new field IDs, renames the members, and fails that caller's compile, which is the intended signal. A parameter or result whose type cannot be flattened at all (a Union, a recursive Product, a Set or Map, an Option of an Option, or a Product holding one of those) crosses whole as an opaque value handle instead ([stateful exports](zig-stateful-exports.md#slice-3-value-handles), slice 3): `const ny_value *` in and `ny_value **` out, the box checked against a structural type tag before anything is copied, the call sharing the argument's value so the host's reference is untouched, and the host releasing a result with the one `ny_release`, whose box carries its own release function, so no per-type symbol is needed.
- **Host bindings.** The sidecar's optional `"zigTables": ["host.zig.json"]` binds capabilities to declarations of a Zig file: `{"format": "nyrwvy.zig-mapping", "version": 1, "source": "host.zig", "capabilities": {"Fs": {"operations": {"readText": {"declaration": "readText"}, "other": {"unavailable": true}}}}}`. Keys are display names, resolved once at emission; every operation of a listed capability must be bound or marked unavailable, and calling an unavailable one is a host failure. `source` must lie at or below the emitted file's directory, because Zig refuses an import above it. A declaration takes an arena allocator created for that host call and freed once its result is copied, then the operation's arguments in declared order, in plain Zig types: `i64`, `f64`, `bool`, `u32`, `[]const u8` for String and Bytes, `?T` and `[]const T`. It returns the same types, `void` for Unit and a struct with the type's display names for a non-generic Product; a result is copied to counted storage and text is checked as UTF-8. A `Result<T, String>` operation's declaration must return an error union, whose error name becomes `Err`; for any other operation an error is a host failure. An export's parameter of a table-bound capability disappears from the C signature, and the export supplies the value. A parameter or result type outside this list is reported as unsupported. A capability the table marks `"handle": "<Zig type in source>"` is a handle capability ([exports that keep state](zig-stateful-exports.md#slice-2-capability-handles), built 2026-11-10): its declarations take a pointer to that type where the handle goes, an operation returning one returns the pointer, and the export side crosses it as an opaque `ny_handle *` to a record that is never freed. An operation entry's `"closes": "<parameter>"` makes it the release: it clears the record under the lock before its declaration runs, so use after close and a second close fail with "Handle is not open" (status 1), as do a null handle and one of another capability. `ny_open_handles()` counts handles not yet closed. A task-bound handle capability is rejected. An operation marked `mayWait` in the graph calls its declaration with the export lock released, so such a declaration must be safe to run beside any other. `Map<String, String>` reaches a declaration as a struct of `keys` and `values`. `libraries/host` binds every capability this way, `Ptys` and `Pty` included. A table's optional `"functions": {"<name>": {"declaration": "<name>"}}` replaces the body of a pure, non-generic function with a declaration of the same form, in library mode only. The declaration borrows its arguments, and its author answers for it agreeing with the Nyr body. A pure function's callers expect no failure, so an error from the declaration stops the process, except as `Err` for a `Result<_, String>` result. `runPure` still uses fakes and never loads a table.
- **Memory and threading.** Arguments are borrowed: an export validates every String, then copies its arguments into counted values the call consumes. Values are reference counted in `std.heap.smp_allocator` (unless a harness set a checking allocator in `ny_values` first), and an export releases its result after copying it, so nothing is reset between calls ([counted library](zig-stateful-exports.md#slice-1-counted-library), built 2026-11-10; Rhifill's `layoutFrame` bench before and after has not been run). `ny_arena` keeps only runtime records (task and cancellation records) for the life of the process. One runtime mutex serialises every export.
- **Still aborts the process:** allocation failure, stack overflow and ReleaseSafe safety checks (bounds, `unreachable`) in generated code (decision consequences: the export is trusted, not sandboxed).

## Decisions (owner, 2026-11-01)

- **A. Plain counts.** `u32` counts, because the runtime lets one thread run at a time under `ny_gate` and its mutex hand-off orders every count change; atomic counts cost a locked instruction per retain and buy nothing while that holds. If parallel task execution shows a measured benefit (a workload where `ParallelAll` or concurrent tasks are CPU-bound), adopt the Koka scheme: mark a value shared when it crosses to another task and count only shared values atomically.
- **B. First milestone without reference counting, then reference counting early.** The per-call arena reset above lands first so real measurement does not wait for F# removal; reference counting follows immediately as the second milestone (see sequencing).
- **C. Export marking in a sidecar.** A list of function names in the workspace's `<snapshot>.backends.json`-style sidecar (tool configuration, outside the fingerprint), not a graph property, until a second consumer needs it.
- **D. Dense array plus hash index for Map and Set.** O(1) lookups and unique updates, O(n) for updating a shared Set or Map, below the O(log n) the language reference documents; the reference records it as a Zig backend difference. If a measured workload suffers from shared updates, switch to a path-copying hash trie (HAMT), which keeps the documented bound at the cost of slower lookups and more runtime code.

## Reason

The arena is the shortcut that blocks real use, but the first real use (a pure per-frame function whose result the host copies) is served by resetting the arena per call, which needs no change to emitted code and so can land while the F# emitter is still the byte reference. Owned parameters with count-of-one reuse are the plan's choice and keep the common functional update (build a list, update a record) allocation-free once unique. Plain counts follow from the scheduler the backend already has. Counting live allocations after every saved case turns the existing conformance suite into a leak suite at no protocol cost.

## Consequences

- A panic in an exported pure function ends the embedding process; Rhifill must treat the Zig export as trusted, not sandboxed.
- Library-mode exports are serialised; a host that calls from several threads waits on the runtime mutex.
- Until 1 lands, only exports whose results the caller copies out are safe to call repeatedly; returning a handle needs reference counting.
- The emitter check stays a hard gate until switch steps 4 and 5 or its early retirement (B): nothing in 1 or the List change merges while it runs.

## Revisit conditions

Revisit A when parallel task execution shows a measured benefit; D when a measured workload updates shared Sets or Maps heavily; the per-call arena reset when an export must return a value that outlives the call; and the whole order if the owner retires the emitter check before F# removal.
