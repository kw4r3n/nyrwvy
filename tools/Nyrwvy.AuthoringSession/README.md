**Status:** Step 8a native-host adapter cutover is blocked and is not merged to main. The accepted requirement that every host read use the typed model is not yet met: fresh opens still retain and serve the JSON model tree ([`main.zig`](../../tools/zig/host/main.zig#L17)). Build, adapter, lifecycle, copied Rhifill C# smoke, and suite validation passed, but that does not satisfy the architectural gate. Do not switch the default or deprecate F# until this gate is resolved and the candidate is reviewed. The eventual cutover PR will mark F# deprecated for normal use while retaining it as reference code and for legacy-schema migration; `NYRWVY_HOST_EXECUTABLE` can still select its `.dll` explicitly. The candidate remains unmerged, so main's default is unchanged. See the [verification record](../../docs/decisions/zig-session-host.md#step-8-candidate-verification-2026-10-31-evidence-not-cutover-approval).

The proposed adapter default is the native Zig executable built by `npm run build:host` into `tools/zig/host/bin/nyrwvy-host` (`.exe` on Windows). This native-only build needs Node 22.6+ and Zig 0.17.0 on `PATH` or selected with `NYRWVY_ZIG`; mise is the repository's recommended way to select the pinned version, but setup does not install mise. Full MCP setup also needs the .NET SDK to build the standalone C# compiler helper; that helper keeps C# backend use available offline. The .NET SDK is not needed to start the non-C# native host. Rebuild after changing the host or switching commits so its embedded Git build identity stays current.

`NYRWVY_HOST_EXECUTABLE` overrides the selected executable. Relative paths resolve from the repository root. A `.dll` override is launched through `dotnet`; a native executable is launched directly. This preserves an operator path to the legacy host during migration.

Do not remove this F# project as part of the adapter cutover. Tagging the final F# commit and pushing that tag, then later preserving reviewed golden evidence for protocol breadth, runtime behavior, and filesystem effects before removal, are separate actions. The five current `tests/host-parity/*.jsonl` files contain requests only, not golden replies. See [the Zig session-host decision](../../docs/decisions/zig-session-host.md) for the cutover, tag, and removal sequence.
