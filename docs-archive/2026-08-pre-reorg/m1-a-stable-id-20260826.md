# M1-A — Production Stable IDs

## Result

M1-A is verified.

Production stable IDs now use RFC 9562 UUIDv7 payloads generated by .NET 10 `Guid.CreateVersion7()`. The in-memory semantic domain remains authoritative through `StableId<'Kind>`; textual domain prefixes are transport/inspection tags and are not duplicated inside the payload.

Examples:

```text
type:<uuidv7>
function:<uuidv7>
node:<uuidv7>
transaction:<uuidv7>
```

The production allocator covers all current stable-ID domains: type, field, variant, function, parameter, pattern binding, graph node, effect, capability, capability operation, capability parameter, obligation, snapshot, and transaction.

`StableIdText` provides typed rendering/parsing and rejects mismatched domains. Existing human-readable fixture IDs remain supported through the testing-only construction path.

Nyason remains compatible: its existing domain tag plus a production UUIDv7 payload produces exactly one typed prefix rather than a duplicated prefix.

## Q-002 status

The basic generation and local-scope portion of Q-002 is resolved by this phase:

- production allocation: UUIDv7;
- in-memory domain safety: `StableId<'Kind>`;
- typed external text: domain prefix plus UUIDv7 payload;
- deterministic tests: explicit testing-only fixture construction.

Cross-repository copy, templating, fork, import, and future semantic-merge identity policy remain deferred and should be treated as a narrower post-M1-A question rather than uncertainty about local ID generation.
